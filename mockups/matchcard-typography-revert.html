Why this happened

The matches list and the home page's "Latest Results" widget both use the same data shape but used to render with different typography. The matches list was tighter (smaller names, more compact, boxed) — that's the look the user remembers from Buenos Aires P1 in Q1 2026.

  • Pre-2026-05-03 (BA era): MatchCard at 12px/15px/weight 800. Compact, dense, boxed card with #141414 background + #222 border. Worked great for power users scanning many rows.
  • 2026-05-03 (commit 00aaeb085): PR "feat(matches): readability uplift on MatchCard" deliberately moved MatchCard up to 13px / 16px / weight 700 so it matched the home page Latest Results card. Spec rationale: "settings work for a single-match deep dive but penalise list scanning, which is the dominant use case." Also switched card surface from solid #141414 to translucent rgba(255,255,255,0.03) and dropped the visible border (live-state left bar still preserved as a status signal).
  • Today (post-uplift): Albania matches render with this newer spec. Player names 1px larger, scores 1px larger, no boxed border, winner weight slightly lighter. This is by design, not an accident — the spec is at docs/superpowers/specs/2026-05-03-matchcard-readability-uplift-design.md.
  • The user is correctly remembering BA looking more compact. Albania uses the post-uplift spec; if you want the BA density back, this is a deliberate revert (not a regression).

Two paths if you want denser back:

(A) Full revert — restore the BA-era numeric values on every MatchCard render. Easy, ~5 numeric changes in one file. Reopens the trade-off the May 3 spec settled (density at the cost of list-scanning ergonomics on the matches page, which is the dominant use case).

(B) Live-only density — keep the current spec on scheduled/finished rows, drop the live-row to BA-era values. Live matches benefit from compactness because the current-point pip + serving indicator + set scores already pack a lot in. More work (status-gated typography), but preserves the uplift gains where they matter and tightens live rows where information density is highest.
