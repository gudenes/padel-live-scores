# i18n Phase 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add English + Spanish internationalization to PadelNachos using `next-intl`, with locale-aware URL routing, ~200 translated UI strings, a language switcher, and locale-aware date/number formatting.

**Architecture:** Install `next-intl`, create i18n config files and message JSONs, restructure app pages into a `[locale]` dynamic segment, compose the proxy with `next-intl` middleware, replace `next/link` and `next/navigation` imports with locale-aware versions, swap hardcoded strings with `useTranslations()`, and add a language switcher to the header.

**Tech Stack:** Next.js 16.2.0, next-intl 4.x, TypeScript 5, React 19.

**Spec:** `docs/superpowers/specs/2026-04-13-i18n-phase1-design.md`

### Task 3: Restructure App Folder into `[locale]` Segment

**Files:**
- Create: `src/app/[locale]/layout.tsx`

This is the critical structural change. All user-facing pages move inside `[locale]/`.

- [ ] **Step 1: Create the `[locale]` layout**

Create `src/app/[locale]/layout.tsx`:

```typescript
import { NextIntlClientProvider, hasLocale } from 'next-intl'
import { getMessages, setRequestLocale } from 'next-intl/server'
import { notFound } from 'next/navigation'
import { routing } from '@/i18n/routing'

export function generateStaticParams() {
  return routing.locales.map((locale) => ({ locale }))
}

export default async function LocaleLayout({
  children,
  params,
}: {
  children: React.ReactNode
  params: Promise<{ locale: string }>
}) {
  const { locale } = await params
  if (!hasLocale(routing.locales, locale)) {
    notFound()
  }
  setRequestLocale(locale)
  const messages = await getMessages()

  return (
    <NextIntlClientProvider locale={locale} messages={messages}>
      {children}
    </NextIntlClientProvider>
  )
}
```

- [ ] **Step 3: Update root layout**

The root `src/app/layout.tsx` currently renders `<html lang="en">`. It needs to:
1. Remove the hardcoded `lang="en"` (the `[locale]` layout handles this via `NextIntlClientProvider`)
2. Keep everything else (metadata, AuthProvider, styles, analytics)

However, since `next-intl`'s `[locale]/layout.tsx` needs to be a server component providing messages, and the root layout has `AuthProvider` (client), the architecture should be:

- Root layout (`src/app/layout.tsx`): renders `<html>` and `<body>` with AuthProvider, analytics, styles — but receives `lang` from params. Since root layout doesn't have access to locale params (it's above `[locale]`), keep `lang="en"` as fallback — the `NextIntlClientProvider` in the `[locale]` layout handles the actual locale context.

Actually, the cleaner pattern is: root layout stays mostly unchanged but removes `<html lang="en">` and replaces with just `<html>`. The page's actual locale is handled by `NextIntlClientProvider`. For proper SEO, we can set the `lang` attribute dynamically via the `[locale]` layout using a `<script>` or by restructuring so the `<html>` tag is in the `[locale]` layout.

The simplest approach for now: keep root layout unchanged. The `[locale]/layout.tsx` wraps children with `NextIntlClientProvider` (does not render `<html>` — that stays in root). SEO `lang` attribute is handled by adding it as a param:

In `src/app/layout.tsx`, change:
```tsx
<html lang="en">
```
to:
```tsx
<html suppressHydrationWarning>
```

And add a client-side script in the `[locale]` layout to set `document.documentElement.lang = locale`. Or better: pass locale to root layout via a different mechanism.

The implementing agent should read the next-intl App Router setup docs to determine the best pattern for Next.js 16. The key requirement is that `<html lang>` reflects the active locale.

- [ ] **Step 2: Rewrite proxy with next-intl composition**

The proxy needs to:
1. Run pre-i18n logic (auth rescue, ops auth, legacy redirects) — these short-circuit with returns
2. Call `next-intl`'s `createMiddleware` for locale routing
3. Add post-i18n cookies (geo, invite ref) to the response

Key changes:
- Remove the `if (pathname === '/')` redirect — `next-intl` handles root routing
- The export must be `export default` (next-intl's createMiddleware returns a default export)
- Import `createMiddleware` from `next-intl/middleware` and `routing` from `./i18n/routing`

The implementing agent should:
1. Read `src/proxy.ts` fully
2. Read the spec's "Proxy Composition" section
3. Read the next-intl docs on composing middleware (search for "composing" in the docs — the pattern is: create handler, call it, modify response)
4. Rewrite the proxy so pre-i18n logic runs first (returning early for ops, auth, legacy redirects), then `handleI18nRouting(request)` runs, then geo/invite cookies are set on the response
5. Update the `config.matcher` to match next-intl's recommended pattern while still excluding api/ops routes

### Task 8: Add Language Switcher to AppHeader

**Files:**
- Create: `src/components/LocaleSwitcher.tsx`
- Modify: `src/components/AppHeader.tsx`

- [ ] **Step 1: Create `src/components/LocaleSwitcher.tsx`**

```typescript
'use client'

import { useLocale } from 'next-intl'
import { useRouter, usePathname } from '@/i18n/navigation'
import { routing } from '@/i18n/routing'

const CHUNKY_BADGE = 'polygon(3% 5%, 97% 0%, 100% 95%, 0% 100%)'
const GREEN = '#7ED321'
const MUTED = '#6B7280'

export default function LocaleSwitcher() {
  const locale = useLocale()
  const router = useRouter()
  const pathname = usePathname()

  const handleSwitch = () => {
    const nextLocale = locale === 'en' ? 'es' : 'en'
    router.replace(pathname, { locale: nextLocale })
  }

  return (
    <button
      onClick={handleSwitch}
      aria-label={`Switch to ${locale === 'en' ? 'Spanish' : 'English'}`}
      style={{
        display: 'flex',
        alignItems: 'center',
        gap: 0,
        background: 'rgba(255,255,255,0.06)',
        border: '1px solid rgba(255,255,255,0.10)',
        clipPath: CHUNKY_BADGE,
        padding: 3,
        cursor: 'pointer',
        flexShrink: 0,
        position: 'relative',
        fontFamily: 'inherit',
      }}
    >
      {/* Sliding indicator */}
      <div style={{
        position: 'absolute',
        top: 3,
        left: locale === 'en' ? 3 : 27,
        width: 22,
        height: 22,
        background: GREEN,
        clipPath: CHUNKY_BADGE,
        transition: 'left 0.2s ease',
      }} />
      {routing.locales.map(loc => (
        <span
          key={loc}
          style={{
            width: 24,
            textAlign: 'center',
            fontSize: 9,
            fontWeight: 700,
            position: 'relative',
            zIndex: 1,
            color: locale === loc ? '#000' : MUTED,
            transition: 'color 0.2s',
            lineHeight: '22px',
            textTransform: 'uppercase',
          }}
        >
          {loc}
        </span>
      ))}
    </button>
  )
}
```
