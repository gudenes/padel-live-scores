# First-Party News Section — `/news` for partnerships and announcements

**Status:** Design (proposed)
**Author:** Claude (with @GuDenes brainstorming session 2026-05-08)

## 1. Goal

Give PadelNachos a place to publish first-party content — strategic partnerships, product launches, milestones — under stable, linkable URLs (`/news/{slug}`) that we can share in press materials, social posts, and partnership decks. Also surface the latest first-party post inside the existing `/feed` so casual users see it without going looking.

This is distinct from two things we already have:
- **`/feed`** — curated/aggregated external articles (RSS) ranked by the feed-scoring engine. Stays untouched.
- **`editorial_posts`** — auto-generated tournament previews/recaps embedded inside tournament pages. Stays untouched.

## 2. Out of scope (v1)

- **Multi-author / author profiles.** Single byline = "PadelNachos team."
- **Scheduled publishing.** Write & publish, no drafts queued for future dates.
- **Tags beyond category.** Just two categories: `Announcements` and `Product`.
- **Comments, reactions, social-share buttons.** Browser native share sheet is sufficient on mobile.
- **Rich-text WYSIWYG editor.** Plain markdown textarea + preview tab.
- **Per-locale editorial control.** Translations are auto-generated by Haiku and shipped as-is. No human review step.
- **Versioning / edit history.** Editing overwrites; no diff or rollback.
- **Pinning/featuring rules in the rail.** Always shows the single most recent first-party post.

## 3. URL structure & navigation

### 3.1 URLs

| URL | Locale | Purpose |
|---|---|---|
| `/news` | EN | Index of first-party posts |
| `/{locale}/news` | ES/PT/IT/FR | Localized index |
| `/news/{slug}` | EN | Detail page |
| `/{locale}/news/{slug}` | ES/PT/IT/FR | Localized detail page |

Slugs are per-locale (each locale row carries its own slug — `partnership-with-x` in EN, `acuerdo-con-x` in ES) so non-English locales get clean SEO URLs. Slug uniqueness is enforced **per `(locale, slug)`** pair.

### 3.2 Navigation entry points

Three discovery paths in:

1. **Rail in `/feed`** — top of the feed page, above existing curated content. Single hero card showing the latest first-party post + "See all →" link to `/news`. (Catches casual feed-browsers.)
2. **AppHeader link** — small "News" entry in the header navigation. (Catches users specifically looking for company news.)
3. **Footer link** — text link in the global footer. (SEO freebie — no extra click cost on screen real estate.)

No BottomNav slot consumed.

## 4. Data model

A new table `news_posts` modeled on `editorial_posts` (locale + translation chain), but extended with the fields a standalone post needs (slug, cover image, draft state, category).

We do **not** extend the existing `articles` table. `articles` is shaped for external curated content (`source_url`, `source_name`, `source_weight`, `favicon_url`, `click_count`) — fields that don't apply here. Mixing the two would muddle both schemas.

We do **not** reuse `editorial_posts`. That table requires `entity_id UUID NOT NULL` (post is attached to a tournament/match/player) — we have no parent entity.

```sql
CREATE TABLE news_posts (
  id            UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  category      TEXT NOT NULL CHECK (category IN ('announcements', 'product')),
  locale        TEXT NOT NULL CHECK (locale IN ('en', 'es', 'pt', 'it', 'fr')),

  -- Content
  slug          TEXT NOT NULL,
  title         TEXT NOT NULL,
  body_md       TEXT NOT NULL,
  cover_image_url TEXT,             -- Supabase Storage public URL (bucket: news-covers)

  -- Translation chain (mirrors editorial_posts pattern)
  translated_from UUID REFERENCES news_posts(id) ON DELETE CASCADE,  -- NULL on EN (source of truth)

  -- Lifecycle
  status        TEXT NOT NULL DEFAULT 'draft' CHECK (status IN ('draft', 'published')),
  published_at  TIMESTAMPTZ,
  created_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at    TIMESTAMPTZ NOT NULL DEFAULT now(),

  -- Provenance (for translations)
  model         TEXT,                -- e.g. 'claude-haiku-4-5' for translated rows; NULL for human-authored EN

  UNIQUE (locale, slug)
);

-- Index supporting the index page (recent published posts, optionally filtered by category)
CREATE INDEX idx_news_posts_published
  ON news_posts (locale, status, published_at DESC)
  WHERE status = 'published';

CREATE INDEX idx_news_posts_category
  ON news_posts (locale, category, status, published_at DESC)
  WHERE status = 'published';

-- Translation lookup
CREATE INDEX idx_news_posts_translated_from
  ON news_posts (translated_from)
  WHERE translated_from IS NOT NULL;
```

**Storage:** new public bucket `news-covers` on Supabase Storage. Images uploaded from the ops UI go here.

## 5. Authoring (ops dashboard)

A new tab on `/ops` titled **"News."** Auth flow follows the existing ops pattern: `ops_token` cookie set by `/ops?token={CRON_SECRET}` login, all `/api/ops/news/*` routes verify the cookie.

### 5.1 Index view (within the tab)

Table of all posts (EN rows only — translations are derived). Columns:

- Title (EN)
- Slug
- Category
- Status (Draft / Published)
- Published at
- Translation status: 4 small chips (ES/PT/IT/FR) — green = translated, grey = pending, red = error
- Actions: Edit, View public page, Delete

"+ New post" button → opens the editor.

### 5.2 Editor view

| Field | Type | Notes |
|---|---|---|
| **Title (EN)** | text input | Required |
| **Slug** | text input | Auto-generated from title (kebab-case, ASCII), editable. Uniqueness check on save. Disabled after publish — slug is sticky. |
| **Category** | dropdown | `Announcements` / `Product` |
| **Cover image** | file upload | Optional. Uploaded to `news-covers/{post-id}-{filename}` in Supabase Storage. Inline preview after upload. |
| **Body (EN)** | textarea + preview tab | Markdown. Preview tab renders with the same prose CSS used on the public detail page. |
| **Status** | radio | `Draft` / `Published`. Default `Draft`. |

Save button at bottom. On save:
- If `status = draft`: insert/update EN row only.
- If `status = published` and post is NEW: insert EN row with `published_at = now()`, then fire-and-forget translation job (see §6).
- If `status = published` and post EXISTS: update EN row, re-trigger translation job (overwrites existing translation rows).

Delete cascades through translation chain via FK `ON DELETE CASCADE`.

### 5.3 Preview before publish

Drafts are accessible at `/news/{slug}?preview=1` — server-side gate on the `ops_token` cookie. Users without the cookie hitting that URL get a 404 (not a 401, to avoid leaking that the slug exists).

### 5.4 What ops can't do (intentional)

- No author selection (single byline).
- No publish-at scheduling.
- No "translate just one locale."
- No tag editing.
- No related-posts override (auto-pick by category recency).

## 6. Translation flow

On publish (or republish), the publish API route runs translations **synchronously** before returning. The ops UI shows a "Publishing & translating…" progress state for the ~20–40s the call takes. No Vercel cron, no background queue, no `waitUntil` — keeps the surface area small and observable.

Per locale `[es, pt, it, fr]`:

1. Read the EN row's `title`, `body_md`, and `slug`.
2. Call Claude Haiku (`claude-haiku-4-5-20251001`) with a prompt asking for translated `title`, `body_md`, and `slug`. Slug must be ASCII kebab-case in the target language (no accents, lowercased).
3. Upsert the result into `news_posts` with `translated_from = en_post.id`, `status = 'published'`, `published_at = en_post.published_at`, `model = 'claude-haiku-4-5'`.

The 4 calls run in parallel (`Promise.all`) so total wall time is bounded by the slowest, not the sum.

Reuse the existing translation pattern from `src/lib/editorial-generator.ts` — same model, same retry/backoff, same JSON-output schema. The prompt differs (news post, not tournament preview) but the plumbing is shared.

**Slug stickiness on retranslate.** If a locale row already exists when republishing, we keep its existing slug and only overwrite `title` + `body_md`. This prevents URL breakage when an author tweaks an EN post — the ES URL someone shared on Twitter doesn't suddenly 404.

**Failure mode:** if a locale fails to translate (timeout, malformed JSON, API error), that row is skipped — the publish API still returns success for the EN post. The public page for that locale falls back via the chain in §7.4. The ops UI shows a red chip for that locale and a "Retry translation" button that calls a separate `/api/ops/news/{id}/translate` endpoint targeting only the missing locale(s).

**Cost ceiling:** 4 translations × ~500 input tokens × $1/MTok + 4 × ~1000 output tokens × $5/MTok = ~$0.022 per post. Negligible.

## 7. Public surfaces

### 7.1 Rail in `/feed`

A new component `<NewsRail>` rendered at the top of `/feed` page, above the existing scored-feed content.

- **Label row:** small PadelNachos logo + bold text "From PadelNachos" + "See all →" link aligned right.
- **Card:** single full-width chunky card (matches the existing `MatchCard` clip-path style). Contains:
  - Cover image (16:9, lazy-loaded)
  - Category badge in top-left corner (`Announcements` / `Product`)
  - Title (2 lines max, ellipsized)
  - Date below title, muted color
- **Tap:** navigates to `/news/{slug}` (locale-aware via `@/i18n/navigation`).
- **Empty state:** if no published posts exist in the user's locale, the rail does NOT render at all. (No "coming soon" placeholder in `/feed`.)

The rail does not affect the scored-feed query below it — they're independent. The feed-scoring engine is untouched.

### 7.2 `/news` index page

Frame: AppHeader + BottomNav (standard app shell). Layout:

1. **Filter chips at top:** `All` / `Announcements` / `Product`. Same chunky-badge style used elsewhere on the app. Default selection: `All`. Selection state held in URL query param (`?category=product`) so it's shareable + back-button-friendly.
2. **Hero:** the most recent published post (matching the active filter) as a full-width chunky card. Cover image, category badge, title (large), date.
3. **Grid below:** remaining posts as smaller cards. 1-column on mobile, 2-column on tablet+. Same card style as the rail card.
4. **Empty state:** if no posts match the current filter, show small graphic + localized "Nothing here yet — check back soon."

Pagination: not needed at the volumes we expect (≤50 posts/year). Render all matching posts on initial load.

### 7.3 `/news/{slug}` detail page

Frame: AppHeader (with back arrow) + BottomNav.

Layout:

1. **Cover image** — full-width 16:9 hero. If no cover, omit and start with the title.
2. **Title** — large, chunky brand font.
3. **Pill row** under title: "By PadelNachos" pill + date pill + category chip. All chunky badge style.
4. **Body** — rendered from `body_md` using existing markdown renderer (whatever the `/about` and tournament-preview pages use). Same prose CSS for typography consistency.
5. **"More from PadelNachos"** — 4 cards from the same category, most-recent-first, excluding the current post. If fewer than 4 in same category, fill with most recent across all categories.

JSON-LD `Article` schema injected in `<head>` (see §8.1). Standard `generateMetadata` with title, description (first 160 chars of `body_md` stripped of markdown), and OG tags pointing at the cover image.

### 7.4 Locale fallback

If a user requests `/{locale}/news/{slug}` but no row exists for that locale:

1. Look up by `(locale, slug)` — if hit, render that locale's post.
2. If miss, look up by `('en', slug)` — i.e., treat the URL slug as an English slug. If hit, render the EN row's content inside the user's locale frame (header chrome stays in user's locale, post body is EN). This handles the case where a user lands on an untranslated post via the index — the index emits `/{locale}/news/{en-slug}` for posts that have no translation in their locale yet.
3. If still miss, 404.

The same fallback applies to the index — when a user is on `/es/news`, the list query returns:
- All `(locale='es', status='published')` rows
- Plus all `(locale='en', status='published')` rows whose `id` is NOT referenced by any `translated_from` from an `es` row (i.e., posts not yet translated to Spanish)

Each card on the index links to `/{locale}/news/{row.slug}` — using the row's own slug, which is ES if it's an ES row, EN if it's an EN-fallback row.

## 8. SEO

### 8.1 JSON-LD on detail page

```json
{
  "@context": "https://schema.org",
  "@type": "Article",
  "headline": "{title}",
  "image": "{cover_image_url}",
  "datePublished": "{published_at}",
  "dateModified": "{updated_at}",
  "author": { "@type": "Organization", "name": "PadelNachos", "url": "https://padelnachos.com" },
  "publisher": { "@type": "Organization", "name": "PadelNachos", "logo": { "@type": "ImageObject", "url": "https://padelnachos.com/logo.png" } },
  "description": "{first 160 chars of body_md, stripped}"
}
```

### 8.2 hreflang

Detail page `<head>` includes `<link rel="alternate" hreflang="{locale}" href="https://padelnachos.com/{locale}/news/{slug}">` for each locale that has a translation row. Index page does the same, pointed at `/news` per locale.

### 8.3 Sitemap

Extend `src/app/sitemap.ts` to include all published `news_posts` rows. Each row contributes one entry per locale that has a translation. `lastmod = updated_at`, `changefreq = monthly`, `priority = 0.7`.

### 8.4 Canonical

Each detail page declares its own URL canonical. EN canonical is `/news/{slug}`. Other locales are `/{locale}/news/{slug}`.

## 11. Phase 1 scope

Everything described in §3–§10 ships together. There is no Phase 2 explicitly planned; if real usage surfaces a need (e.g., demand for editorial pieces, tags, multi-author), each is a small additive change to a known shape.

## 12. Open questions / risks

- **Slug-collision UX in ops.** If an author types a slug that's taken, we error on save. Acceptable for v1; if it becomes annoying we can preflight-check on slug-input blur.
- **Cover image cropping.** No in-app crop tool; users must upload pre-cropped 16:9. Document this in the ops UI as helper text.
- **Translation latency.** Haiku usually returns in <10s per locale. The fire-and-forget pattern means the EN post is live before translations land. A user hitting `/es/news/{slug}` in those first ~30s gets the locale-fallback (EN body, ES frame). Acceptable.
- **Translation quality on partnership posts.** Auto-translate-and-ship is the user-chosen tradeoff for minimum effort. If a translation embarrasses, the ops UI's "Retry translation" or manual edit (re-write the locale row's body_md directly) are the escape hatches.
- **Empty state on index when migrating.** First time anyone visits `/news` before we publish post #1, they see the empty state. Acceptable — no chrome breakage.
