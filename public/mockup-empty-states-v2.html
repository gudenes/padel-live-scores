How the click resolves

Decision logic on LIVE tap:
1. Probe "is anything globally live?" — uses existing hasLiveMatches for today's cache; if today isn't cached yet, do a quick /api/matches/by-date?date=today&liveOnly=1 check (or piggyback on the calendar payload — add a hasLiveNow field).
2. Live exists: setActiveIso(today) → setFilters(status: live-only) → existing render shows live matches.
3. No live anywhere: show toast, do NOT engage the filter, do NOT change day. Pill flashes pressed then springs back.
What about the date-empty case (past day with no matches)?
Separate from this change. The existing "Next matches: <date> ›" CTA already handles it. If you want to bundle a "Back to today" secondary into the same PR, easy add — otherwise punt to a follow-up.
