Token parity check

Every primitive in the mockup uses the literal value from the codebase, not an approximation:

--bg-base #1A1A1A --bg-card #141414 --bg-elev #0A0A0A --green #7ED321 --green-neon #BCE83B --muted #6B7280 --men #4A9EFF --border 6% white cp-badge CHUNKY badge cp-card CHUNKY card cp-button CHUNKY button

Primitives matched

  • Level pill — 8px / weight 800 / GREEN on rgba(126,211,33,0.12) / badge clip-path. Matches page.tsx:805.
  • Gender M/W toggle — 56×28, knob 24×22, MEN_BLUE base, badge clip-path on both outer and knob. Matches page.tsx:706.
  • FOLLOW button — not bright green; it's muted text on 6% white, button clip-path, plus icon. Matches FollowButton.tsx:117.
  • Tabs — 12px / weight 800 / GREEN active with 2px underline at 15%–85%. Matches page.tsx:837.
  • Stat cards — BG_CARD with card clip-path, 22px value, 10px uppercase label. Matches page.tsx:1511.
  • Timing banner — 3px green border-left, soft green tint, "12 days" right-aligned in GREEN. Matches page.tsx:1554.

Decided

  • Expanded height: 280 px (preserves today's banner height)
  • Cover at collapse: keep as faint background (brightness 0.35)
  • Tabs: sticky at 62 px below the collapsed bar (matches today's behavior)
  • FOLLOW: inline in the identity row when expanded, moves to top chrome when collapsed (matches player page pattern)
  • Collapsed title: full tournament name at 18 px, fades in with FOLLOW

Implementation diff (vs current branch)

  • Delete the 49-line standalone hero block I added in Task 8 (top of src/app/[locale]/(app)/tournaments/[id]/page.tsx).
  • Restructure Row 1 of the existing sticky header into the new collapsing layout: cover image + gradient as backdrop, top chrome (back / M-W / FOLLOW) layered above, expanded title block at bottom-left.
  • Remove Row 2 (the tournament info card) — its contents move into the expanded title block of the collapsing hero.
  • Add scroll listener on window (the page is the scroll context, not an inner container in prod) that drives one CSS custom property --hero-progress: 0 → 1. Height, opacity, image translate, and darkening all interpolate from that single value.
  • Tabs row already exists; just give it position: sticky; top: 62px;.
  • No-cover fallback — when cover_image_url is null, banner has no image and no darkening; expanded view still shows the title block over flat var(--bg-elev). Collapse still happens, so behavior feels consistent.
  • Accessibility — honors prefers-reduced-motion by snapping between expanded and collapsed without interpolation. All interactive elements stay reachable at any progress value.
